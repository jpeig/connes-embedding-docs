1. What this repository shows

Since Ji–Natarajan–Vidick–Wright–Yuen (MIP*=RE, 2020), the Connes Embedding Problem is known to have a negative answer — but the decisive input comes from quantum complexity theory, a field away from the operator-algebra community that owns the problem. That creates a practical trust problem: to use ¬CEP one has to take a long interactive-proof-theoretic construction on faith, and the operator-algebraic part of the argument (Kirchberg/Tsirelson passage, game algebras, traces) has never been laid out at a level of rigor where every step can be inspected.

Where to start (10 minutes). Read §2 below — one theorem and its four-line certificate. Then run the three commands of §8 to re-verify everything yourself. If operator systems and spectral truncations are your area, §7 is self-contained, fully proved, and the best second stop.

This repository does two things about that:

  1. Part I(a) — the main result. The entire operator-algebraic reduction from the game separation down to a non-Connes-embeddable tracial state is formalized and verified by the Lean proof kernel. The complexity-theoretic input enters at exactly one named point — an explicitly stated axiom recording what MIP*=RE provides — and the verifier prints that this is the only non-standard input. Everything else (the dilation and lifting arguments, free-product permanence, the u.c.p. extraction, the final wiring) is checked down to the axioms of the logic.

  2. Part I(b) — the map. A formalized conditional architecture for a complexity-free ¬CEP — two reduction chains through flexible Hilbert–Schmidt stability and the Dogon–Vigdorovich obstruction, with every open ingredient isolated as an explicitly marked leaf — together with an honest account of why the known purely operator-algebraic attack routes fail (§6). The blunt summary: the machine-checked map keeps ending at the same place — the uncomputability mechanism is, at present, the only known certificate.

Part II is a separate, self-contained bonus in the spectral-truncation direction: the compression of the shift algebra to a finite spectral block is verified to be a genuine operator system (unital, self-adjoint, not closed under multiplication) carrying a non-degenerate Lipschitz seminorm from the commutator with the truncated number operator, with the finite-stage Rieffel compact-quantum-metric-space axioms. See §7.

2. The main theorem

The headline declaration is FaithfulSingleCapstone.lean:

/-- **Single-citation-scaffold ¬CEP.** `#print axioms` = kernel trio plus exactly
`kirchberg_game_separation_ucp_structured`; the Boca dilation, finite-dimensional
liftability, free-product permanence, u.c.p. extraction, and final wiring are
kernel-checked. -/
theorem cep_false_operator_algebraic_single_scaffold :
    ZFib.CEP.ConnesNonEmbeddableWitness

where ConnesNonEmbeddableWitness bundles a C*-algebra with a tracial state that admits no trace-preserving embedding into a tracial matrix ultrapower — a witness refuting CEP.

The single named input is:

/-- **Structured MIP*=RE citation.** The KPS/JNVWY synchronous separation, repackaged to
return the canonical universal measurement algebra with its
`MeasurementAlgebraStructure` (faithful: the qc-model construction IS on
`C*(F(n,m)) ≅ ∗ⁿ Cᵐ`) together with the absence of a u.c.p.-amenable (qa) trace. -/
axiom kirchberg_game_separation_ucp_structured : ...

In words: there is a finite synchronous game whose quantum-commuting model lives on the universal measurement algebra (the n-fold free product of m-outcome PVM algebras, C*(F(n,m)) ≅ ∗ⁿ Cᵐ), whose canonical trace admits no u.c.p.-amenable approximation. This is precisely the content MIP*=RE supplies through the synchronous-games literature; it is stated, not proved, here — deliberately, so that the boundary between "verified operator algebra" and "cited complexity theory" is a single searchable line of code.

Everything downstream of that line is kernel-checked, including the step that was until recently a second citation: free-product permanence of approximate u.c.p. liftability (Boca-dilation territory) is now proved internally (bocaFreeProductPermanence_holds_internal), which is what collapsed the perimeter from two citations to one.

The verified certificate (see §3 and scripts/AxiomCheck.lean):

'ZFib.CEP.cep_false_operator_algebraic_single_scaffold' depends on axioms:
  [propext, Classical.choice, Quot.sound,
   ZFib.CEP.kirchberg_game_separation_ucp_structured]

propext, Classical.choice, Quot.sound are Lean's three standard foundational axioms, present in essentially every Mathlib-based development. The fourth line is the game separation. There is no fifth line.

3. How to read a machine-checked claim (one minute, no Lean background)

Three vocabulary items suffice to audit this repository:

  • The kernel. Lean proofs are not "checked by a program that looks reasonable" — every proof term is re-verified by a small trusted kernel. If the repository compiles, every theorem is a theorem of the ambient logic given its listed axioms.
  • axiom = a named citation. An axiom declaration introduces a statement without proof. It is the formal analogue of "by [JNVWY 2020]". Crucially, axioms are tracked: the command #print axioms someTheorem makes the kernel print the exact set of axioms the proof of someTheorem ultimately rests on. Nothing can be smuggled in — a citation used three layers down still shows up in the list.
  • sorry = a visible, marked gap. A sorry is an explicitly unfinished proof. It is also tracked: any theorem whose proof (transitively) touches a sorry shows the pseudo-axiom sorryAx in its #print axioms output. The main theorem's list above contains no sorryAx; the conditional architecture's entry points do, by design — their gaps are exactly the enumerated open lemmas of §5.

So the audit protocol for a skeptical reader is: build the repository, run the axiom check, and read the printed lists. scripts/AxiomCheck.lean additionally freezes the main theorem's list — if any change to the code silently enlarged it, the build would fail.

4. The complexity-free conditional architecture

Could ¬CEP be reached without MIP*=RE — by purely operator-algebraic and geometric-group-theoretic means, i.e. by exhibiting a non-hyperlinear group? That is open. This repository formalizes the, to our knowledge, sharpest known reduction skeleton, with the open cores carried as explicit hypotheses (Prop arguments — not axioms, not sorry):

Chain A — rank-1 route (ConditionalChain.lean):

theorem qce_implies_cep_false (p : Nat) [Fact (Nat.Prime p)]
    (hQCE : QCE_p p) : ConnesNonEmbeddableWitness

QCE_p is a dimension-uniform Hilbert–Schmidt rigidity statement on the congruence edge of the Bass–Serre amalgam SL₂(ℤ) ∗_{Γ₀(p)} SL₂(ℤ); from it, flexible HS-stability of the amalgam, then a Dogon–Vigdorovich central-extension obstruction forces a non-hyperlinear group, then the group-von-Neumann dictionary produces the witness.

Chain B — high-rank route (HighRankChain.lean):

theorem acm_implies_cep_false (L : HighRankLatticeData) (hACM : ACM L) :
    ConnesNonEmbeddableWitness

ACM (approximate congruence-monomiality) is the regular-sector half of flexible HS-stability for a high-rank lattice; the rest of the chain reuses the Dogon–Vigdorovich 2025 higher-rank (T;FD) mechanism and the same shared tail.

Both composition bodies are sorry-free — the wiring is complete and kernel-checked; what remains are the named link lemmas of §5 and the two open cores. The fully proved special case (the tempered subcategory: the 2×2 Gram positivity gap plus the Deligne 2√p/(p+1) < 1 temperedness bound) is in TemperedGap.lean — zero sorry, zero project axioms; a good entry point for a reviewer.

Status verdicts from our own analysis (§6): the open core of Chain A appears to be false — an exact multiplicity computation shows the torus-phase obstruction that QCE_p would need has asymptotically vanishing relative mass — and the open core of Chain B is ¬CEP-hard (proving it would already produce the non-hyperlinear group). The chains are retained because the formalized wiring is precisely what turns those diagnoses into sharp, checkable statements about where the difficulty lives.

6. The map of dead ends

What makes ¬CEP resistant to a purely operator-algebraic proof? Each of the following routes was pursued and closed; the details live in the paper (§5), the diagnoses are summarized here.

  1. Chain A's core (QCE_p) fails for a structural reason. The distinguishing data for edge rigidity sits on a block of dimension Θ(k) inside congruence representations of dimension p^{k-1}(p+1) — asymptotically vanishing relative mass. Optimal alignment succeeds asymptotically (the torus-phase obstruction washes out at rate √k·p^{-(k-1)/2}; confirmed numerically), so the rigidity QCE_p demands is not there. Root cause: SL₂(ℤ[1/p]) has no property (T); nothing rigidifies the amenable congruence tower.

  2. Rigid (same-dimension) stability is forbidden as an axis. By the Becker–Lubotzky mechanism, an infinite hyperlinear property-(T) group cannot be HS-stable — so the flexible notion is the only live one, and it is exactly the one whose high-rank instances are open.

  3. Chain B's core is ¬CEP-hard, not a reduction. Flexible HS-stability of a 2-Kazhdan high-rank lattice (Dogon–Vigdorovich's own Problem 1.3) would already produce an explicit non-hyperlinear group. Our sharpest attack on it — a coupled op-norm/HS Hölder bootstrap against the (T;FD) spectral gap — was broken by our own adversarial review: the two halves need mutually exclusive regimes (the op-2 defect is rank-localized; hiding it requires a growing complement, which destroys the Hölder constant the other half needs).

  4. The monomiality route (high-rank, edge-free) has a false load-bearing assumption. Approximate congruence-monomiality fails: cuspidal representations are not flexibly-HS-monomializable within the required o(dim) budget.

  5. The non-soficity route targets the wrong invariant. The cosystolic-expansion program (Chapman–Lubotzky §6.1; Dikstein–Dinur–Lubotzky) aims at non-sofic groups — and sofic ⟹ hyperlinear, so a non-sofic group gives no non-hyperlinear group and no ¬CEP.

  6. The intrinsic invariants are provably blind. Cost, ℓ²-Betti numbers, cocycle superrigidity, sofic entropy are orbit-equivalence / ℓ²-spectral / sofic-relative quantities; hyperlinearity is a trace-approximability property. Treeable relations are sofic at every cost and every ℓ²-Betti value, so no "invariant ≠ expected value ⟹ non-hyperlinear" implication exists. The known candidate witnesses are even built to satisfy Lück's determinant conjecture.

The honest conclusion, and the reason this repository's main theorem is shaped the way it is: every known purely operator-algebraic route to an explicit non-hyperlinear group is currently dead, foreclosed, aimed at the wrong invariant, or exactly as hard as ¬CEP itself. The value-gap discontinuity that MIP*=RE detects is invisible to the standard invariants — which explains why a complexity-free proof has stayed out of reach, and why isolating the complexity input as a single named statement (rather than pretending it away) is the right interface for the operator-algebra community.

7. Part II — spectral truncations as operator systems

Independent of CEP, the repository contains a machine-checked finite stage of the spectral-truncation program (Connes–van Suijlekom): compressing the shift algebra A = C*(S) on ℓ²(ℕ) by the spectral projection Q_M = 1_{[0,M]}(N) of the number operator.

Verified, at zero project axioms (Lean's three standard axioms only):

  • OS_M = Q_M A Q_M is a genuine operator system — unital, self-adjoint, and not closed under multiplication: the witness (Q_M S* Q_M)(Q_M S Q_M) ≠ Q_M (S*S) Q_M = Q_M is proved as the matrix identity diag(1,…,1,0) ≠ diag(1,…,1) (T_FIB_OS_TRUNCATION_OPERATOR_SYSTEM.lean).
  • The Lipschitz seminorm L_M(a) = ‖[N_M, a]‖ is non-degenerate on the shift and degenerate on the diagonal: [N_M, S_M] = S_M ≠ 0 while [N_M, ·] kills the diagonal masa — so the metric structure genuinely lives on the shift.
  • Finite-stage Rieffel CQMS axioms for (OS_M, L_M) (T_FIB_OS_CQMS.lean), and the full-band Lipschitz-kernel computation [N_M, S^p] = p·S^p (T_FIB_OS_FULL_BAND_KERNEL.lean).

The natural continuation — Gromov–Hausdorff convergence of the truncated state spaces to the limit, transplanting the Connes–van Suijlekom S¹ Fejér argument — is not claimed here; it is the proposed joint next step.

(Part II is built on a small self-contained ℓ²(ℕ) substrate, TruncationSubstrate.lean. Two reading notes for the source files: the fib/ZFib prefixes throughout are the parent project's namespace convention and carry no mathematical content here; and any stray internal tracking labels in comments come from the parent project's bookkeeping — only the theorem/def statements are load-bearing, and the axiom check is the arbiter of what is proved.)

8. Reproducing the check

Requirements: elan (the Lean toolchain manager); everything else is fetched automatically.

git clone <this repository>
cd connes-embedding-lean
lake exe cache get     # fetch prebuilt Mathlib (~a few GB, one-time)
lake build             # verify every proof in the repository
lake env lean scripts/AxiomCheck.lean   # print + freeze the axiom certificates

If lake build succeeds, every theorem in the repository is kernel-verified from its listed axioms. scripts/AxiomCheck.lean fails to elaborate if the main theorem's axiom list ever differs from the four-line list of §2. The same sequence runs in CI on every push (.github/workflows/ci.yml); the resulting axiom-report.txt is archived as a build artifact.

Toolchain: Lean v4.30.0-rc2, Mathlib pinned at 1a5bbc7d3785.
